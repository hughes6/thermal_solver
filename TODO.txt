Zuken Mega Script — Modular Source Project
This project started as a source-code refactor of the working V26 all-in-one launcher.
It retains the original 14 tools and now includes Zuken Script Runner as a 15th tool,
with 24 separately maintained tool modules.
The Block Maker builder and formatter have since been updated to support
per-SCH-symbol Saber Parameter 1 values; all other tools remain unchanged.

Run and edit
1. Extract the ZIP as a whole folder, rather than running only the
   Zuken_Mega_Script.py file from the archive.
2. Copy your four original workbook templates into templates/ (see the
   included PLACE_ORIGINAL_TEMPLATES_HERE.txt). Their actual bytes were
   not included in the earlier Python script.
3. Run py Zuken_Mega_Script.py from the project directory.
4. To change one tool, edit only its file in tool_scripts/.
5. To check source integrity without connecting to E3 or SQL:
   py Zuken_Mega_Script.py --self-test.
Build a single Windows executable
Run py build_exe.py from the project directory. This is the reusable
command for future releases. The output is dist/Zuken_Mega_Script.exe.

The reusable build script bundles all tool_scripts/ files and now collects
wxPython (wx) and pandas for Zuken Script Runner. Install those packages
in the Python environment that builds the EXE before calling py build_exe.py:
py -m pip install wxPython pandas
The fixed output name is always dist/Zuken_Mega_Script.exe. The other
pdfplumber, pdfminer, Tkinter, E3, pyodbc, openpyxl and win32com build
settings are unchanged.

The launcher still extracts only the requested tool to the existing stable
E3_Mega_Runtime_V26 folder, and honors its hash/backup mechanism for
user-edited runtime copies. Saved workbook selections remain in the same per-user settings location.
The Templates tab provides only Download; it no longer imports or overrides originals.

Important: If you previously edited source files under your local
E3_Mega_Runtime_V26 folder, they will take precedence over newly edited
files in tool_scripts/ (by design). To apply new bundled changes, first
back up your modifications; only then update the matching runtime copy.
Scope of verification
The project validates compilation and byte-for-byte identity of all tool
sources against V26. Actual PyInstaller, E3 COM, SQL, and Microsoft Excel
interop must be exercised on your Windows workstation.
Block Maker — SCH Saber Parameter 1 (2026-11-25)
The Block Maker workbook may now have a Saber Parameter 1 name in row 3
for each repeating connector group: K3, P3, U3, Z3, ... (five-column pitch).
Blank entries are skipped. Use your updated Block Maker workbook; the ZIP does
not contain the user's modified original Excel template.

The builder stores each nonblank name as the symbol-level E3 attribute
saberParam1 on the exact corresponding SCH CABBLOCK. It does not display
or format that attribute in the builder. Equipment Identification remains
created with its historical E3 spelling Equipment Identifacation but is
not automatically activated or formatted.

After the first existing formatter pass, a dialog pauses for the operator to
turn on Saber Parameter 1 attribute text for each populated SCH block in
E3. Equipment Identification is optional: enable it only on the blocks
where you want its text formatted. Click DONE to verify the required Saber
text is active. If any required Saber text is not yet visible, the dialog
remains open so you can activate it and retry; Cancel exits without the
second pass. No automatic DisplayAttribute() operation is done for these
SCH header attributes.

Once ready, the second formatter pass formats the active Saber and optional
Equipment text in black, bold, centered, with the workbook-defined text size.
Saber is at top - 1.1; Equipment is top - 1.5 when Saber is visible,
or keeps the former top - 1.1 position for an Equipment-only block.
No inactive Equipment Identification text is formatted or made visible.

Testing: A synthetic E3 COM test suite checks correct Excel cell offsets,
per-symbol attribute creation/readback, active text formatting, optional
Equipment behavior, and waiting for missing Saber text. These tests do not
replace validation in a real Windows E3 project.
Zuken Script Runner tab (2026-11-25)
Open the dedicated Zuken Script Runner tab and click Open. The original
wxPython checklist appears in a separate process. Select Wirelist, Cable Table,
End to End, or All. For Print Labels, also select Cable Table. The runner
reads the currently open Zuken E3 project, writes the selected Excel reports,
and exports saved reports as PDFs using Microsoft Excel COM. Closing the
checklist without generating makes no changes to the E3 project.

The six runner files live together under tool_scripts/zuken_script_runner/.
AppGuiCode.py is capitalized exactly as imported by appmain.py, avoiding
case-sensitive import failures. The EXE routes this wxPython tool through
--run-tool zuken_script_runner in a separate worker so it cannot collide
with the Tkinter launcher. Errors are written to its runtime
launcher_output.log; the worker returns nonzero rather than silently
reporting success. The runner was tested with mocked E3/wxPython dependencies,
not actual Windows COM, Excel or a live E3 project.
